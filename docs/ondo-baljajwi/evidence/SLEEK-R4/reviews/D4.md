## D4-R4-001 — KO 지도와 일부 edge dialog의 접근 가능한 이름이 영어로 남는다

- Severity: `S2`
- Fingerprint: `D4-KO-A11Y-DEFAULT-ENGLISH-CONTROLS`
- Surfaces / flows: `CITY-LIVE`, app shell, Table unavailable, Chat locked / `FL-001`, `FL-003`, `FL-014`
- Evidence:
  - 실제 브라우저를 KO, `390×844`, Seoul map으로 열었을 때 MapLibre control/gesture가 `Use ⌘ + scroll to zoom the map`, `Zoom in`, `Zoom out`으로 노출됐다.
  - `k-tour-id-app/features/ondo/map/map-entry-b.tsx:491-505`는 `cooperativeGestures: true`와 `NavigationControl`을 생성하지만 MapLibre locale message를 전달하지 않는다.
  - `k-tour-id-app/features/ondo/app/ondo-app.tsx:51`의 canvas 이름은 `ONDO travel food app`으로 고정돼 있다.
  - `k-tour-id-app/features/ondo/connect/connect-overlays.tsx:160,383`의 edge sheet 이름도 각각 `Table unavailable`, `Chat locked`으로 고정돼 있다. 화면 본문만 KO로 바뀐다.
- Why actionable: KO 사용자의 시각적 본문은 한국어인데 핵심 지도 조작 도움말과 일부 dialog 이름은 영어다. screen-reader/voice-control 사용자는 한 작업 안에서 언어가 바뀌고, 해당 이름을 한국어로 탐색할 수 없다.
- Acceptance:
  1. KO map의 cooperative-gesture 문구와 zoom control accessible name을 자연스러운 한국어로 제공하고 EN에서는 기존 영어를 유지한다.
  2. app canvas, unavailable Table sheet, locked Chat sheet의 accessible name도 현재 locale을 따른다.
  3. KO/EN 각각 `390×844`, `1440×1000` 실제 `/ondo-b`에서 visible help 및 computed accessible name을 검증한다. app-owned copy와 MapLibre control을 모두 assertion 대상으로 둔다.
  4. focus order, zoom 동작, map fallback은 변하지 않는다.

## D4-R4-002 — Public profile 저장이 browser-local preview를 실제 공개처럼 말한다

- Severity: `S2`
- Fingerprint: `D4-PROFILE-PUBLICATION-CLAIM-SESSION-ONLY`
- Surfaces / flows: `PROFILE` / `FL-015`
- Evidence:
  - 실제 브라우저에서 account를 만든 뒤 `ID → Edit public fields → From=Canada → Show publicly → Save selected fields`를 수행했다.
  - 결과는 `Only selected fields are public`과 toast `Selected public fields saved.`였다. 편집 전·중·후 어디에도 이 값이 브라우저/session-local preview이고 실제 public profile로 publish되지 않는다는 문구가 없다.
  - KO도 `선택한 필드만 공개 중`, `공개하기`, `선택한 필드 저장`, `선택한 공개 필드를 저장했어요.`로 같은 주장을 한다 (`k-tour-id-app/features/ondo/profile/profile-panel.tsx:9-45,119-123`).
  - 실제 구현은 `window.sessionStorage`에서 profile을 복원·저장할 뿐이다 (`k-tour-id-app/features/ondo/shared/state/ondo-provider.tsx:206-239,257-273`). 외부 profile publication은 없다.
  - nationality를 복사하지 않고 self-declared consent를 요구하는 기존 문구는 올바르지만 publication boundary를 대신하지 않는다.
- Why actionable: 사용자는 location/language가 다른 사람에게 공개됐다고 이해할 수 있다. 개인정보 공개 상태와 실제 동작이 불일치하므로 단순 데모 어조 문제가 아니다.
- Acceptance:
  1. 편집 진입 전, consent toggle 인접부, 저장 결과에 `이 브라우저의 로컬 프로필 미리보기에서만 공개로 표시되며 실제 사용자에게 게시되지 않는다`는 동등한 KO/EN truth를 지속적으로 표시한다.
  2. CTA/toast/status도 실제 publication 완료를 주장하지 않도록 `Save profile preview`, `Saved in this browser` 계열로 맞춘다.
  3. identity-check nationality 미복사와 필드별 self-declared consent 문구는 유지한다.
  4. normal no-QA account flow에서 KO/EN `390×844`, `1440×1000`, reload/session restore까지 테스트한다.

## D4-R4-003 — Table-full 결과가 같은 화면의 “고정 로컬 예시” 계약과 모순된다

- Severity: `S2`
- Fingerprint: `D4-TABLE-FULL-INVENTED-LIVE-RACE`
- Surfaces / flows: `TABLE-DETAIL`, `TABLE-JOIN-FAIL` / `FL-003`
- Evidence:
  - 실제 브라우저에서 `?scenario=table-full`로 Table을 열고 `Join preview`를 실행했다.
  - 화면 상단은 `Dates and seat status are fixed examples, not current availability. No live host or reservation exists; joining changes only this local preview.`라고 명시한다.
  - 같은 화면의 결과는 `The last seat filled while your request was processing. Choose another nearby Table.`이었다. KO도 `요청하는 동안 마지막 자리가 찼어요.`라고 한다 (`k-tour-id-app/features/ondo/connect/connect-overlays.tsx:192-194`).
  - 고정 truth는 `k-tour-id-app/features/ondo/connect/tables-entry.tsx:19-30`에 있고, 일반 network failure는 이미 `No live host or reservation was contacted`라고 정확히 구분한다 (`connect-overlays.tsx:185-188`).
- Why actionable: live seat mutation과 처리 중 경쟁 요청이 존재했다고 서술하지만 제품은 이를 수행하지 않는다. 명시적 truth label 바로 아래에서 반대 사건을 만들어 신뢰 경계를 무너뜨린다.
- Acceptance:
  1. full 결과를 `This fixed preview is configured as full`처럼 local fixture 결과로 표현한다. live seat 변화, 요청 처리 중 경쟁, host/reservation 접촉을 암시하지 않는다.
  2. KO/EN 모두 동일 Table·시간·장소 맥락과 nearby recovery CTA를 유지한다.
  3. `table-full` actual browser branch에서 top truth와 action result가 서로 모순되지 않음을 assertion하고, status announcement/focus도 유지한다.

## D4-R4-004 — 기존 10번째 스탬프 문장이 자체적으로는 visit evidence를 과장한다

- Severity: `S3`
- Fingerprint: `D4-VISIT-RECORD-UNQUALIFIED-CONFIRMED`
- Surfaces / flows: pre-existing stamp branch in `CHECKOUT-RECEIPT` / `FL-004`
- Evidence:
  - `state.stamps === 10 && visitState !== "accepted"`에서 `The tenth visit was confirmed separately before this checkout.` / `열 번째 방문은 이전에 별도 확인되어 있습니다.`를 표시한다 (`k-tour-id-app/features/ondo/commerce/checkout-overlay.tsx:139-144`).
  - 같은 block의 앞 문장은 이 기록이 재현 가능한 preview이며 GPS·QR·merchant evidence가 아니라고 올바르게 한정한다. 그러나 상태 결과 문장 자체는 `preview/local record`를 생략하고 실제 방문 확인처럼 읽힌다.
  - 이 branch는 `k-tour-id-app/tests/e2e/ondo-commerce-browser.spec.ts:74-79`에서 실제 reachable state로 고정돼 있다.
- Why actionable: 문맥 전체를 읽으면 위험은 제한되지만, 복귀·스크롤·보조기술 읽기에서 결과 문장만 소비하면 일반적인 verified visit으로 오해할 수 있다. 다른 visit 상태가 일관되게 `simulated/preview`를 반복하는 것과도 다르다.
- Acceptance:
  1. 결과 문장 자체에 `previous simulated/local preview visit record`를 포함하고 `confirmed visit` 단독 표현을 제거한다.
  2. KO/EN pre-existing `10/10` branch와 새 `9→10` branch 모두 실제 현장 증거가 아님을 각 상태에서 독립적으로 이해할 수 있어야 한다.
  3. My/Trust의 `Simulated visit records` 분류와 terminology를 맞춘다.

## D4-R4-005 — 생성한 영문 표기를 official/sourced 장소 이름처럼 전면 배치한다

- Severity: `S2`
- Fingerprint: `D4-ROMANIZATION-PRESENTED-AS-OFFICIAL-NAME`
- Surfaces / flows: `CITY-LIST`, `PLACE-PEEK`, `PLACE-DETAIL`, `MY` / `FL-001`, `FL-011`
- Evidence:
  - 실제 EN Seoul list에서 `Gukbapjaengi`가 primary, `국밥쟁이`가 secondary로 보였고, `pizza` 검색은 Seoul 3곳/Busan 5곳을 정상 반환했다. list에서는 Latin primary가 생성된 transliteration이라는 label이 없다.
  - list 자체는 `sourced food places`, `official place records`라고 말한다 (`k-tour-id-app/features/ondo/map/map-entry-b.tsx:34-92`). primary name은 `venueDisplayName(...)`, secondary는 한글명만 출력한다 (`map-entry-b.tsx:387-394`).
  - `venueDisplayName`은 source의 official English name을 읽는 함수가 아니라 자체 음절 조합 romanizer다 (`k-tour-id-app/lib/ondo/venues/display.ts:14-31`).
  - detail과 My도 Latin 결과를 primary로 두고 secondary를 `${Korean name} · Transliterated for navigation`으로 구성해, label의 문법적 대상이 한글명처럼 보인다 (`canonical-place-overlay.tsx:299-302`, `my-entry.tsx:30-35`).
  - 음식 alias는 search haystack에만 들어가고 place facts에는 보이지 않았다. alias truth boundary는 정상이며 이 finding은 표시 이름의 출처 표시에 한정한다.
- Why actionable: source가 제공하지 않은 Latin string을 official/sourced place record의 대표 이름으로 오인시킨다. 특히 기계식 romanizer 결과(`Sseobeuweisejongdaejeom` 등)는 navigation 보조 표기이지 공식 영문 상호가 아니다.
- Acceptance:
  1. official Korean name을 명확한 source name으로 유지하고 생성 Latin string에는 `Transliteration for navigation · not an official English name`과 동등한 표시를 직접 연결한다.
  2. city list, peek/detail, search result, My saved place에서 같은 용어·위계를 사용한다. label을 한글명 뒤에 붙여 대상을 모호하게 만들지 않는다.
  3. `pizza`, `chicken`, `coffee` 등 alias는 계속 search-only이고 place name/fact/source payload를 변경하지 않아야 한다.
  4. 6개 viewport와 KO/EN에서 긴 romanization wrapping, CTA 밀림, accessible name을 회귀 검증한다.
