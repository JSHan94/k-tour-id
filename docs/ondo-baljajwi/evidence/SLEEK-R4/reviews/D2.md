The visual task is preserved, but keyboard position is not.

### D2-R4-002 · place peek cannot be dismissed with Escape and Close loses its opener

- Round / reviewer / tuple: `SLEEK-R4 · D2 · 05f3002 / 2d7e0f0 / 74100b05`
- Dimension: `A11Y` with `USABILITY` impact
- Flow / checkpoint: `FL-001 CANCEL / RETURN`
- Surface / component path / state: `place/*` non-modal place peek; selected place after List → result
- Locale / viewport / input: EN `390×844`; keyboard; also visually inspected at all six viewports and KO/EN registered variants
- Reproduction:
  1. Open Seoul → List and activate `Gukbapjaengi`.
  2. Confirm initial focus is `Close place` in the `aria-modal="false"` dialog.
  3. Press Escape while the close button is focused.
  4. Press `Close place` and inspect focus.
- Expected: Escape dismisses the sheet, and either Escape or Close restores focus to the invoking result when retained or a stable fallback such as `List` when the result list was replaced by the map.
- Actual: Escape has no effect. Pointer/Enter activation of `Close place` removes the sheet and leaves focus on `BODY`; the visible map, filters, shell navigation, and After19 controls remain outside the non-modal dialog, so this is not explained by a modal trap.
- User impact: the common dismissal key is inert, while successful dismissal drops keyboard users at the document root instead of the result/map decision they came from.
- Evidence:
  - live browser: dialog remained visible after both dialog-level and focused-button Escape; after Close, `{dialogCount:0, active:{tag:"BODY"}}`;
  - canonical baseline: `tests/visual/ondo-b-flow-pixels-mobile.spec.ts-snapshots/B-PX-PLACE-PEEK-EN-FL-001-en-390x844-mobile-chromium-darwin.png`.
- Severity / classification: `S2 · objective`
- Violated invariant: shared Sheet keyboard/close behavior in `VISUAL_SYSTEM`; `FL-001 CANCEL/RETURN` interaction clarity.
- Acceptance test:
  - From a List result and from a map marker, Escape and the close control both dismiss exactly one peek.
  - Focus returns to the invoking result if present; otherwise it lands on the visible `List`/`Map` toggle selected by the transition contract.
  - Repeat at `360×800`, `390×844`, `430×932`, `801×1000`, and `1440×1000`, KO and EN; background controls remain usable because the peek stays intentionally non-modal.
- Confidence: `HIGH · deterministic on repeated focused Escape and Close`
- Duplicate fingerprint: `place-peek-escape-noop-close-focus-body`
- Proposed fix / owner / status: add Escape handling and an explicit opener/fallback reference to the non-modal place peek; `owner: place sheet`; `OPEN · fix SHA pending · retest pending`.

### D2-R4-003 · double-clicking mobile feedback submission opens the unrelated Leave Table confirmation

- Round / reviewer / tuple: `SLEEK-R4 · D2 · 05f3002 / 2d7e0f0 / 74100b05`
- Dimension: `USABILITY`
- Flow / checkpoint: `FL-003 TERMINAL / CANCEL`
- Surface / component path / state: `connect/*` Table chat → post-meal feedback → recorded chat state; compact-mobile reflow
- Locale / viewport / input: EN `390×844`; rapid pointer double-click; normal single activation and `1440×1000` double-click do not show the failure
- Reproduction:
  1. Join `First gukbap together`, open chat, check in, and open feedback.
  2. Select Yes in each feedback group.
  3. Double-click `Submit feedback` once.
  4. Observe the feedback terminal state after the first activation and the second activation's target after compact reflow.
- Expected: the submission is idempotent; the result appears once and no different control is activated by the second click in the same physical gesture.
- Actual: feedback is recorded, then the second click lands on the newly revealed `Leave Table` control at the same compact-mobile location and opens `alertdialog "Leave this Table?"`. No leave is finalized because the confirm dialog still blocks it, but the user is unexpectedly placed in a destructive confirmation.
- User impact: a common rapid/tremor input changes the task from successful feedback to an unrelated exit decision and creates a credible accidental-leave path.
- Evidence:
  - live browser: immediately after one `dblclick`, `Feedback recorded. No overall score was created.` and `alertdialog "Leave this Table?"` were both present; Cancel restored chat;
  - canonical pre-submit visual: `tests/visual/ondo-b-flow-pixels-mobile.spec.ts-snapshots/B-PX-FEEDBACK-KO-FL-003-FL-015-ko-390x844-mobile-chromium-darwin.png`.
- Severity / classification: `S2 · objective`
- Violated invariant: rapid/double-input idempotency and single-task interaction clarity.
- Acceptance test:
  - At `360×800`, `390×844`, and `430×932`, execute one native double-click and a 50–150 ms two-click sequence on Submit in KO and EN.
  - Assert one feedback receipt, unchanged Table membership, and zero Leave/Report dialogs.
  - Keep a disabled submission row or input shield in the same geometry until the second-click window is exhausted; verify keyboard single activation still returns to the chat result.
- Confidence: `HIGH · exact native double-click reproduction at canonical mobile width; desktop negative control recorded`
- Duplicate fingerprint: `feedback-submit-mobile-reflow-ghost-click-leave`
- Proposed fix / owner / status: make feedback completion idempotent against the whole click sequence and prevent the result reflow from exposing another action under the pointer; `owner: connect feedback/chat`; `OPEN · fix SHA pending · retest pending`.
