## Findings

### D1-R4-001 · desktop navigation rail occludes core content on short-height desktops

- **Round / reviewer / tuple:** `R4 · D1 · 05f3002 / 2d7e0f0 / 74100b05`
- **Dimension:** `USABILITY`
- **Flow / checkpoint:** `FL-001 ENTRY + DECISION`
- **Surface / component / state:** Nation introduction and City map; `ondo-main-nav` desktop rail against the Nation lead paragraph and `map-b_preferenceSummary`; `NATION`, `CITY-LIVE`
- **Locale / viewport / input:** independently reproduced in `EN` and `KO`; `1440×800` headless Chromium and `1512×801` live Chrome; pointer and keyboard geometry
- **Reproduction:** open a clean `/ondo-b`, choose `Explore as a guest`, inspect the Nation introduction, then open Seoul and inspect `Tune interests / 관심사 설정`. Keep the desktop width and reduce height to 800/801px.
- **Expected:** the persistent rail reserves a clear gutter and has zero intersection with readable hero copy or any independent map control.
- **Actual:** at `1440×800`, the first nav item `[151,226,54,87]` intersects the Nation lead paragraph `[153,208.5,320,36]` by `52×18.5px` (`962px²`), hiding the left of the second line. On City, the same nav item intersects the preference control `[145,198,154.5,44]` by `54×16px` (`864px²`). At `1512×801`, KO reproduces `52×18px` on the Nation paragraph and `54×15px` on the preference control. The screenshot visibly loses paragraph glyphs and the control's lower-left boundary beneath the rail.
- **User impact:** the core first-use explanation becomes partially illegible and two independent hit/focus regions occupy the same pixels. This is a measurable geometry regression, not an aesthetic preference.
- **Evidence:** live `1512×801` Nation KO screenshot SHA-256 `ae7d065660961c2c14ab9e14e2841584a15aa6d5911e84ae7432ffc02d56b3f0`; live City KO `5b6e1be4a90d2e9eb69a71ade04ddea9dd6d53ecf8d70541b962251f8bfe7b60`; independent Chromium `1440×800` Nation `5d3565f5fa25657b4a38cb10e14fa4e96dd505e9fde5d710cec085bc6328bb18`. The six-width canonical baseline is rooted at `k-tour-id-app/tests/visual/ondo-b-flow-pixels-*.spec.ts-snapshots/`; `1440×1000` remains clear and proves the height dependency.
- **Severity / classification:** `S2 · objective · actionable on one reproduction`
- **Violated invariant:** `09_UX_UI_COMPONENT_STATE_MATRIX` requires independent control overlap `0`; `VISUAL_SYSTEM` requires clear hierarchy and negative space.
- **Acceptance test:** for `KO` and `EN` at both `1440×800` and `1512×801`, assert zero-area intersection between the desktop rail and (a) Nation heading/lead copy, (b) City segmented filters, preference control, map key, and result bar. Text pixels and focus outlines must remain unobscured; all six frozen viewports must retain zero horizontal overflow and unchanged task reachability.
- **Proposed fix:** reserve a desktop rail gutter for content/controls, or use a height-aware rail position that begins below the top content/control band. Do not solve it by shrinking type or touch targets.
- **Owner / status / fix SHA / retest:** `product shell + map · OPEN · none · pending`
- **Confidence / duplicate fingerprint:** `high · short-desktop-rail-overlaps-nation-copy-and-preference-control`

### D1-R4-002 · desktop venue rows have no perceptible hover affordance

- **Round / reviewer / tuple:** `R4 · D1 · 05f3002 / 2d7e0f0 / 74100b05`
- **Dimension:** `AESTHETIC`
- **Flow / checkpoint:** `FL-001 DECISION`
- **Surface / component / state:** City list; `.venueList li button`; `CITY-LIST`
- **Locale / viewport / input:** KO and EN visual structure; reproduced at `1440×1000` and `1512×801` with a mouse hover
- **Reproduction:** open Seoul, switch to List, hover any venue row away from its chevron.
- **Expected:** desktop hover supplies a restrained but perceptible response consistent with the subtle/hairline system.
- **Actual:** the hovered button remains `background: rgba(0,0,0,0)` with `cursor: default`; no visible line, fill, or motion delta identifies the whole row as interactive. Keyboard focus remains a separate visible path.
- **User impact:** minor loss of desktop tactility and discoverability; chevrons still communicate clickability, so task completion is not blocked.
- **Evidence:** exact-browser `1440×1000` City screenshot SHA-256 `50df31fa4dc3f5ea97fa26c01cf5121216eedfe741e19a7f9c82d51fdfc23ac2`; computed hover receipt above. Relevant baseline: `k-tour-id-app/tests/visual/ondo-b-flow-pixels-desktop.spec.ts-snapshots/B-PX-CITY-LIST-EN-FL-001-en-1440x1000-desktop-chromium-darwin.png`.
- **Severity / classification:** `S3 · subjective aesthetic candidate · non-actionable without 3/5 consensus or a locked-token violation`
- **Acceptance test:** under `@media (hover:hover)`, hovering a venue row produces a subtle, non-heat visual delta and a pointer cursor; focus-visible remains at least as clear and reduced-motion behavior is preserved.
- **Proposed fix:** use the existing `Subtle` surface or hairline tone for a small row-wide hover response; avoid elevation or a card shadow.
- **Owner / status / fix SHA / retest:** `map list · CANDIDATE · none · pending consensus`
- **Confidence / duplicate fingerprint:** `medium-high · desktop-venue-row-no-hover-delta`
