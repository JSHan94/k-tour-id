## Finding R5-D1-001 — focus is rendered with the danger color

- Severity: **S2**
- Fingerprint: `focus-visible/global/danger-red-rgb-179-68-56/instead-of-focus-blue-1d66d1`
- Surface: context-preserving place-detail overlay; the same global focus treatment is visible on focused controls elsewhere.
- Locale: EN repro; color-token defect is locale-independent.
- Viewports reproduced: `360×800`, `390×844`, `430×932`, `768×1024`, `801×1000`, `1440×1000`.
- Canonical evidence: the focused Back control is visible in the committed `B-PX-PLACE-DETAIL-EN` frame in all three snapshot families, including `...360x800...png`, `...390x844...png`, and `...1440x1000...png`.

Reproduction:

1. Seed the ordinary EN B session and open `/ondo-b?venueId=mois-0021cd596bc5b2a922ad`.
2. Expand the canonical place detail. The dialog moves focus to the icon-only `Back to place summary` button.
3. Observe the focus ring, then press Tab through `Close place`, `Directions`, and `Save`.
4. Repeat at each frozen width; the wrong semantic color is unchanged.

Expected:

- `docs/ondo-execution/07_VISUAL_INTERACTION_SPEC.md` defines `--focus: #1D66D1` for keyboard focus and requires a visible `2px --focus` ring with a `2px` offset.
- Error meaning remains on the separate danger token; focus must not borrow an error/destructive semantic.

Actual:

- Focused Back/Close controls render `outline: rgb(179, 68, 56) solid 2px; outline-offset: 2px` at every frozen width.
- Keyboard traversal to `Directions` and `Save` renders the same red family as a semi-transparent `3px` outline with `0px` offset, adding an internal focus-geometry inconsistency.
- `rgb(179, 68, 56)` is a danger-red treatment, visually adjacent to the specified danger token rather than the required blue focus token.
- The red ring is baked into the accepted place-detail baselines, so the pixel suite faithfully preserves the defect instead of detecting it.

Impact:

- Keyboard focus reads as an error/destructive state on neutral navigation and primary actions.
- It breaks the explicit semantic color separation and introduces a systematic interaction-state inconsistency across otherwise restrained neutral surfaces.
- The ring remains visible and geometrically adequate, so this is not an S1 access blocker; it is a reproducible S2 visual/a11y-integrity failure.

Acceptance condition:

- Route every focus-visible treatment through the designated focus token (`#1D66D1`) while preserving `2px` thickness and `2px` offset.
- Re-capture and manually inspect focused icon, primary, secondary, sheet, dialog, and navigation controls in KO and EN across the six frozen widths.
