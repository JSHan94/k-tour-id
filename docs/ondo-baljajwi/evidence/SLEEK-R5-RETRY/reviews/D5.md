## Findings

### R5R-D5-001 — browser history does not represent traveler navigation (S2)

**Reproduction**

1. Enter Seoul city map as a guest.
2. Switch Map → List.
3. Select Roba, then open Place details.
4. Inspect browser navigation history and use browser Back.

**Expected**

The traveler should be able to close the deepest surface with browser Back and return through the exact prior place/list/filter/city context.

**Actual**

Immediately before and after the complete map → list → place → detail sequence, Chromium reported the same history entry: count `13`, current index `12`, entry id `40`, URL `/ondo-b`. The open detail state and selected venue were never represented in history. Browser Back therefore targets the preceding unrelated document entry instead of restoring the prior in-product surface; in-product close controls are the only safe workaround.

**Impact**

Back is a primary mobile and browser navigation affordance. Losing the current traveler stack can discard city, filter, query, and selection context even though the equivalent in-app close path preserves it. This is a material usability defect, but the application remains usable through explicit close controls.

### R5R-D5-002 — offline truth banner and cached/fixture timestamp are absent (S2)

**Reproduction**

1. Load the Seoul map to the ready state.
2. Emulate offline network conditions, confirm `navigator.onLine === false`, and dispatch the browser offline event.
3. Return to the map surface.

**Expected**

Canonical execution spec `07_VISUAL_INTERACTION_SPEC.md` requires an `오프라인 · 저장된 정보` banner and a cached/fixture timestamp while offline.

**Actual**

The map remained `data-map-state="ready"`. No offline/오프라인 copy, status or alert, or cached/fixture timestamp appeared.

**Impact**

Existing content remains usable, but the traveler cannot tell that data may be stale or that the product is operating from retained evidence. This obscures the provenance/resilience boundary.

### R5R-D5-003 — expired 19+ proof disables After19 without a reason banner (S2)

**Reproduction**

1. Seed the exact selected canonical After19 venue with age state `AGE-VERIFIED`, `after19=A19-ON`, and an `ageExpiresAt` value in 2020.
2. Reload the exact venue.

**Expected**

Per `07_VISUAL_INTERACTION_SPEC.md`, an expired 19+ proof must preserve the selected venue, return the product to day mode, and show why access changed.

**Actual**

The venue selection was preserved and the reducer correctly changed the mode to `A19-OFF`, but no status/alert and no expired/만료 reason text appeared.

**Impact**

The safety state is conservative, but the silent change makes access appear arbitrary and gives the traveler no recovery explanation.

### R5R-D5-005 — keyboard focus is lost after map retry succeeds (S2)

**Reproduction**

1. Force the map into its tile error state.
2. Activate Retry map with the keyboard or click it.
3. Restore deterministic tile responses and wait for the ready state.

**Expected**

Successful recovery should retain or restore a visible keyboard focus anchor on the recovered map/list region or the action that initiated recovery.

**Actual**

The map recovered from attempt 1 to attempt 2 with 40 source items and 8 rendered features, but `document.activeElement` became `BODY`, with no role, tab stop, or test id.

**Impact**

The retry works visually, but keyboard and assistive-technology travelers lose their location immediately after recovery. This conflicts with the focus continuity and visible-focus requirements in `07_VISUAL_INTERACTION_SPEC.md`.
