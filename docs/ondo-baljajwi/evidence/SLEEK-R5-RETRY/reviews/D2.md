## Finding

### R5R-D2-001 — S2 — Browser Back abandons a nested discovery task and Forward cannot restore it

On both `390×844` and `1440×1000`, ONDO does not add history entries for city, filtered list, place peek, or place detail. Browser Back from the open Roba detail therefore leaves the current `/ondo-b` document instead of unwinding to the same place summary or Seoul results. Returning with browser Forward remounts the nation screen; the city, list, filter, selected place, peek/detail level, and focus context are all gone.

Reproduction:

1. Enter `/ondo-b`, choose Seoul, switch to List, and open Roba.
2. Open Place details. The address bar remains exactly `/ondo-b`; history length is unchanged by every nested transition.
3. Invoke browser Back.
4. Observe navigation to the prior document (or `about:blank` on a direct-entry tab) instead of the Roba summary/Seoul list.
5. Invoke Forward. Observe the nation chooser, not the interrupted detail task.

The route supplies working in-product exits: Escape from Account Gate returns focus to Save on the same detail, another Escape returns focus to Place details on the same peek, and the visible back/close controls preserve context. Browser Back is nevertheless a standard web navigation path, especially on mobile, and currently discards several user decisions with no recovery. This is raw **S2**: the app and stored identity data remain safe, but the primary discovery task is lost and must be rebuilt.

Acceptance should make browser history unwind nested state predictably (detail → peek → the same filtered/list city context → nation), preserve the selected city/query/place and a sensible focus target, and define a stable Forward result. Exercise this in KO and EN at the six frozen widths, including a direct-entry tab and an app page with a real prior history entry.
