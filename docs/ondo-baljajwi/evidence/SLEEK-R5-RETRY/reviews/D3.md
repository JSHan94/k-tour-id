## Findings

### D3-R5R-001 — S2 — My and Labs expose nested duplicate `main` landmarks

The outer ONDO application root is a `<main>`. The My surface mounts another `<main data-testid="ondo-my-entry">` inside it, and the affected Labs terminal surfaces mount `<main data-testid="labs-overlay">` inside it. Axe reports all three moderate-impact landmark rules:

- `landmark-main-is-top-level`
- `landmark-no-duplicate-main`
- `landmark-unique`

Reproduction is invariant across all six frozen viewports for these four cases:

- `B-PX-MY-EN`
- `B-PX-LABS-TRAIT-FAIL-KO`
- `B-PX-LABS-BRIDGE-FAIL-EN`
- `B-PX-LABS-BRIDGE-SUCCESS-EN`

That is 24 case×viewport observations for each rule. Multiple indistinguishable and nested main landmarks impair landmark navigation for screen-reader users. Replace the nested surface-level `<main>` elements with non-landmark containers or give the document one top-level main landmark with correctly named subordinate regions.

### D3-R5R-002 — S2 — City map controls collide in short landscape and 400% reflow

The live city map fails the stated no-overlap constraint at every required short-landscape probe and at the 320 CSS-pixel reflow equivalent:

| Viewport | Actual collision |
|---|---|
| `844×390` | `Food place or neighborhood` search input overlaps `My location` |
| `740×360` | search input overlaps `My location`; `List` overlaps `After 19` |
| `926×428` | desktop side navigation overlaps the search input and map attribution |
| `320×800` (400% reflow equivalent) | `Tune interests` overlaps `After 19` |

These are independent hit-testable controls intersecting by more than the 2px geometry tolerance. The collisions are visible in the captured Chrome frames; at `740×360`, for example, the locate control is drawn inside the search field and the List/After 19 controls intersect. At `926×428`, the left navigation obscures search copy and attribution. This is not horizontal document overflow—the root remains width-contained—but it does compromise legibility and reliable pointer targeting.
