**Reproduction**

1. Open `/ondo-b`, choose `Explore as a guest`, then open Seoul.
2. Set the viewport to `1440×800` while the desktop side navigation is active.
3. Inspect the lower-left map key. The navigation rail covers the `12× Places` prefix and part of the key's reading area.

**Expected**

The side navigation and map key have zero intersection; the full `12× Places · 82 Simulated score` distinction remains visible. This is required by the frozen `nav/CTA overlap 0` and `independent control overlap 0` visual invariant and by the cartography rule that neutral counts and ONDO heat must remain immediately distinguishable.

**Actual**

- At `1440×800`, navigation rect = `x 145..209, y 220..580`; map-key rect = `x 145..380.578125, y 540..596`; overlap = `64×40 px`.
- At actual `1512×801`, navigation rect = `x 181..245, y 220.5..580.5`; map-key rect = `x 181..416.578125, y 541..597`; overlap is again present.
- At the frozen `1440×1000` case, navigation rect = `x 145..209, y 320..680`; map-key rect = `x 145..380.578125, y 718..774`; overlap = `0`. The defect is therefore height-responsive and is not visible in the frozen tall desktop baseline.
