# ONDO · 해커톤 연동 개발 요약

## 1. 목표와 범위

기존 지도 기반 웹앱의 목업 화면에 **OmniOne CX + OpenDID + OmniOne Chain**을 연결합니다. 장소 1곳에서 신원 확인, 패스 발급·제시, 체험 혜택 사용, 체인 기록까지 실제로 동작하는 여정이 목표입니다. 현재 공개 앱은 목업이며, 아래 연동은 개발 대상입니다.

이번 구현은 **신원 확인 경로 1개 · 패스 1종 · 비금전 체험 혜택 1개 · 체인 이벤트 1종**으로 한정합니다. Sui, 실제 원화/스테이블코인 충전·결제·환불, 상점 예약 API, 여권·외국인등록증 실연동은 제외하고 목업으로 유지합니다.

해커톤의 모바일 신분증 활용은 CX로 구현하고, OpenDID·OmniOne Chain 활용 과제도 함께 구현합니다. 세 기술 모두 이번 개발 범위에 포함합니다.

## 2. 대표 사용자 플로우

```text
지도에서 장소 선택 → 체험 혜택 확인·동의
 → 모바일 신분증 확인 (CX) → 서버에서 결과 검증
 → K-Tour 패스 발급·지갑 보관 (OpenDID VC)
 → 해당 혜택에 필요한 증명 제출·검증 (OpenDID VP)
 → 사용 가능 여부 확인 → 사용자가 “혜택 사용” 확정
 → 서버에 1회 사용 기록 → 같은 장소로 복귀
                         └→ OmniOne Chain 기록·확정 결과 조회
```

VC는 발급받아 보관하는 증명서, VP는 사용자의 동의로 제출하는 증명입니다. 앱에는 기술명 대신 “신원 확인”, “패스 받기”, “혜택 사용”처럼 행동 중심으로 표시합니다. 혜택은 실제 결제·예약이나 매장의 제공 의무가 없는 해커톤 체험용입니다.

## 3. 구현할 작업

| 작업 | 구현 내용 |
|---|---|
| **모바일 신분증 확인 · OmniOne CX** | 실제 앱 호출·복귀와 결과 검증을 연결합니다. 서버가 확인 결과를 검증하고 이후 패스와 동일 사용자로 연결합니다. 취소·실패·만료도 처리합니다. |
| **패스 발급·제시 · OpenDID** | 기존 OpenDID 서버와 실제 holder(사용자 지갑)를 활용해 VC 1종을 발급·보관합니다. 장소·혜택 목적에 맞는 VP를 요청하고, 서명·발급자·소유자·만료·철회 상태를 서버에서 검증합니다. |
| **혜택 사용 · 서비스 API/DB** | 세션, 자격 판정, 사용 확정, 처리 상태 조회 API를 구현합니다. 같은 사용자·캠페인은 한 번만 사용하도록 하며, 중복 요청이나 재시도로 추가 사용이 생기지 않게 합니다. |
| **사용 결과 기록 · OmniOne Chain** | 혜택 사용 이벤트 1종을 계약에 기록하고 실제 확정 결과를 조회합니다. DB 사용 기록과 체인 처리 상태는 분리하며, 기록 실패 시 재처리합니다. 개인정보·신분증·VC 원문은 체인에 올리지 않습니다. |
| **기존 화면 연결·검수** | 장소 상세에 체험 혜택 액션을 연결하고 실제 API의 동의·대기·완료·실패 상태를 반영합니다. 외부 앱 복귀나 새로고침 후에도 진행 상태를 재조회하고 같은 장소로 돌아오게 합니다. |

착수에 필요한 환경은 **CX 테스트 계정·신분증/기기·callback 설정, OpenDID 서버·실제 holder, OmniOne Chain 네트워크·계약 배포/서명 권한**입니다. CX·Chain의 계정·접속정보·API 키와 최신 연동 매뉴얼은 주관사 제공 자료를 사용합니다.

## 4. 완료 기준과 일정

- 실제 기기에서 위 여정을 끝까지 시연하고, 동일 사용 건의 CX 검증·VC/VP·체인 확정 결과를 확인할 수 있습니다.
- 취소·잘못된 증명·만료·철회 시 사용을 막고, 중복 요청·응답 유실·재접속 시 중복 사용 없이 복구합니다. 체인 거래 ID만 받은 상태는 확정으로 표시하지 않습니다.
- 실행 가능한 소스, 환경변수 목록(비밀값 제외), DB/계약 설정, 시연 URL과 검증 결과를 전달합니다. 실제 연동과 목업 결과는 구분합니다.
