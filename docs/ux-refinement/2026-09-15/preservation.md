# PRD 보호 경계 · 이번 UX 변경

상태: 구현 전 보호 규칙. 기존 UI 구조가 아니라 사용자 가치·결정·업무 상태를 보호한다. 최신 사용자 요청과 Deployment Spec이 과거 Toss-grade/production catalog보다 우선한다.

| 보호 항목 | UX에서 바꿔도 되는 것 | 삭제·자동 추론하면 안 되는 것 | 기준 |
|---|---|---|---|
| 지도 우선·선택 설정 | 취향 편집을 한 시트로 묶기, 지역 선택 재사용 | 지도 전 KYC/설문 강제, 취소로 기존 취향 초기화 | Deployment G01/02 |
| 장소/콘텐츠 | 공통 media·카드·주 행동, 근거 disclosure | 다른 매장 사진, 검증 없는 canonical ID/제휴 부여 | G03 |
| 저장·계정 | 맥락 안에서 필요한 확인만 요청 | Account=Person 추정, 원 장소·초점 손실 | G04 |
| 신원·패스·제시 | 반복 안내 축약, 같은 작업 틀 | 동의/목적/요청자/철회·만료·발급·보관·제시·복구 상태 | G05/06 |
| After 19 | 탐색 필터와 시각 표현 정리 | 테마와 연령 자격 혼합, 일반 야간 식당 차단 | G07 |
| 함께 먹기 / 매장 예약 | 동일 매장에서 두 목적을 명확히 구분 | 참여·대화 권한·안전 조작, 좌석 예약과 Table 합치기 | G08/08-R |
| 충전 | 주문 맥락 복귀, 수단 위계, 합리적인 진행 표시 | source/destination 분리, 도착 전 credit, unknown 재송금 | G09/09-S |
| 결제·환불 | 하나의 주문/영수증·환불 진입 | quote/재동의, authorized/captured, 원 주문 귀속·부분 환불·hold·중복 방지 | G10, §6 |
| 파트너/증거 | 소비자 밖의 접힌 검수·증거 화면 | 정산과 실제 지급/체인 확정을 같은 상태로 취급 | G11 |
| Labs·방문·배지 | 기본 여정에서 보조 위치로 이동 | 결제를 방문으로, 샘플 signer를 실제 자격으로 사용 | G12 |
| 설정/개인정보 | 관련 설정 묶기, 용어 통일 | 동의 없는 데이터 삭제, sample account 작업으로 실제 계정 처리 주장 | G13 |
| 해커톤 체험 | 같은 장소의 비금전 혜택 작업으로 일관된 UX | CX/OpenDID/Sui/OmniOne 책임 삭제, 금전 checkout을 실제 체험 권한으로 대체 | Sui 추가 명세 §2/4 |

## 공통 판정

- 자격·지원 여부가 unknown일 때 부정이나 성공으로 바꾸지 않는다.
- 제출 전 취소는 업무 무변경. 제출 후 닫기/뒤로가기는 작업 취소가 아니며 동일 pending/unknown 작업과 재조회 경로를 보존한다.
- 거래/지갑 기록은 현재 세션 목업이다. 더 매끈한 복원을 만들기 위해 기존 receipt만으로 잔액/자격을 재생성하지 않는다. 새 수명 계약이 필요하면 명시 결정한다.
- 일반 금액은 KRW. 선택한 코인 충전에서는 asset/network/fee/수령액/서명 내용을 보여준다. 모바일에서도 자세한 설명에 접근 가능해야 한다.
- 3도시·EN/KO/JA·light/dark/system 및 After 19 독립성을 유지한다.
- 미해결 PRD 누락은 담당·해결 계획·검증 기준 없이 구현 완료 또는 배포 합격으로 바꾸지 않는다.
