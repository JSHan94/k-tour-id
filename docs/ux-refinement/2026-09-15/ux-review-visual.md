# Independent UX review — visual, motion and accessibility

검토일: 2026-09-15. 상태: **독립 첫 판정 동결본 — 3인 합의 아님**. 시각/모션/접근성 역할이며 다른 두 UX 리뷰 문서는 읽지 않은 상태에서 작성했다. [decisions.md](decisions.md)의 UX-01–09, [visual-standard.md](visual-standard.md), [preservation.md](preservation.md)를 완독했다. 콘텐츠 조사 담당으로 작성한 사진 manifest는 읽었으므로 UX-06에 그 근거를 공개한다.

앱 코드 수정·새 브라우저 시나리오 실행은 하지 않았다. 아래 관찰은 기존 브라우저 캡처 5개와 제한된 코드 확인에 기반한다. 캡처의 미감 검토를 실제 기기/키보드/명암비/스크린리더 검증 통과로 표현하지 않는다.

## 3. 가장 먼저 반영할 세 가지

1. **목적에 맞는 제목과 CTA:** 022의 충전·결제 혼용을 해소하고, UX-01의 완료 후 목적지를 짧게 표시한다. 사용자가 “어떤 돈을 어디로 보내는가”를 이해하는 데 새 화면보다 중요하다.
2. **매장/오퍼 공통 표현:** 031의 Zest 주문은 식사 고정 문구와 국그릇 아이콘을 제거한다. 예: Review your offer / Zest와 업종 중립 아이콘. Your visit, ready도 거래/방문 완료를 연상시키지 않는 확인 단계 제목으로 바꾸는 편이 낫다. 사진이 없으면 중립 아이콘을 유지한다.
3. **읽을 수 있는 샘플 활동:** 027의 말풍선은 이미 48×48 최소 터치 영역이 있지만 Sample은 8px, +1은 10px이다. 정보의 진위를 알리는 Sample을 12px 이상으로 제안하고 필요한 만큼 카드를 넓힌다. 확대 후 지도 후보 간 간격/상단·타임라인 비침범을 다시 확인한다. 이를 숨기거나 상세에만 옮기는 것은 반대한다.

031에서 동의하지 않은 상태에도 CTA가 시각적으로 검정색인 것만으로 권한 우회 버그라고 판정하지 않았다. 실제 코드는 동의 확인/안내 경로가 있다. 개선 시 클릭하면 누락 동의를 명확히 안내·포커스하며 아직 결제되지 않았음을 유지해야 한다. 단순히 버튼을 흐리게 만들어 이유를 모르게 하는 것도 피한다.

## 4. 모션: 이미 있는 자산과 보호할 동작

소스 근거:

- [sample-temperature-presentation-b.ts](../../../k-tour-id-app/features/ondo/map/sample-temperature-presentation-b.ts): ephemeral snapshot store이며 계정/자격/저장 권한이 아니다. 이전 도시 cleanup이 새 도시 snapshot을 지우지 않도록 owner를 확인한다.
- [temperature-timeline-b.tsx](../../../k-tour-id-app/features/ondo/map/temperature-timeline-b.tsx), 약 73–93/174–205행: reduced-motion·visibility를 보고, 지도 source의 setData 완료 후 동일 frame을 publish한다. 223–248행은 reduced-motion에서 반복 재생 대신 명시적 시간 단계 이동을 제공한다.
- [traveler-activity-map-b.tsx](../../../k-tour-id-app/features/ondo/map/traveler-activity-map-b.tsx), 17–25/35–54/76–90행: 동일 painted snapshot을 구독한다. 활동 cue는 2개이고 focus 시 ID를 고정한다. 실제 기여/방문으로 저장하지 않는다.
- [traveler-activity-map-b.module.css](../../../k-tour-id-app/features/ondo/map/traveler-activity-map-b.module.css), 2/8–14행: 48px 타깃, 8/10px 텍스트, focus-visible, reduced-motion, forced-colors 대응을 확인했다.

따라서 새 “라이브” 애니메이션 엔진을 만들 근거는 없다. 선택 장소의 작은 추세 표시가 필요하면 같은 frame의 해당 ID만 읽고, 도시/좌표/원천을 임의 생성하지 않는다. 문구는 Sample activity / 샘플 활동처럼 유지한다. 비동기 도착의 늦은 이전 프레임이 새 도시·새 선택 장소를 덮는 반례도 확인한다.

자동 진행 표시를 매초 aria-live로 읽지 않는다. 시작/일시정지/명시적 단계 이동은 이해 가능한 이름과 상태를 제공하고, 사용자가 읽는 정보나 조작의 위치를 움직이지 않는다. 배경 탭에서는 기존 중지 규칙 유지, 복귀 시 여러 누락 프레임을 급속 재생하지 않는다.

## 5. 구현 후 최소 수락 게이트

- **범위:** 390px 기준 022/027/030/031의 before/after를 나란히 검수. 320px, EN/KO/JA 긴 문구, light/dark, 짧은 높이에서도 제목·선택값·동의·고정 CTA가 가려지지 않아야 한다. 이번 캡처는 이 변형 전체의 PASS 증거가 아니다.
- **터치/포커스:** 주요 조작 44px 이상, sticky CTA 52px 이상. 결제/충전 수단 카드 전체와 크레딧/상세 펼침도 손가락으로 누를 수 있어야 한다. Tab/Shift-Tab/Escape, 시트 포커스 트랩, 완료·취소 시 원 조작 복귀를 확인한다.
- **색/읽기:** 본문 대비 4.5:1, 큰 글자/의미 있는 UI 경계 3:1을 프로젝트 검수 목표로 측정한다. 아직 실측하지 않았다. 분홍/금색 차이만으로 샘플/실제/자격/선택을 구분하지 않고 텍스트·아이콘·상태를 함께 제공한다.
- **금액/의미:** 원가·혜택 적용 전후·지불액·사용 가능 잔액을 구분한다. 일반 금액은 KRW, 코인 선택에서는 asset/network/fee/수령액을 모바일 tap 가능한 상세로 제공한다. “Available”은 혜택 적용 완료의 증거가 되지 않는다.
- **모션:** pause/reduced-motion/document-hidden/도시 전환/선택 유지 5개 상태를 검사. frame 구독자는 동일 minute/ID를 표시하고 별도 임의 sequence를 만들지 않는다. 모션을 꺼도 정보와 조작이 없어지지 않는다.
- **사진:** 승인된 동일 지점만, 설명과 크롭 일치, 주목적인물이 있으면 별도 검토. loading/error에서 레이아웃이 무너지거나 다시 다른 매장 사진으로 대체되지 않음. photo credit과 날짜/예시 구분을 숨기지 않는다.
- **보호:** 원본 quote·동의·pending/unknown·hold·refund/order 귀속은 비작성자 반례 리뷰에서 검증. 시각 일관성을 위해 서로 다른 업무 상태를 하나로 합치는 변경은 반려한다.

이 판정은 **시각/접근성 역할의 첫 피드백**이다. UX-08은 사용자 응답 전 보류이며, 나머지 방향도 다른 두 역할 및 PRD 보호 판정과 조정한 뒤 구현한다.

첫 평가의 Sample 12px 제안은 선호안이었다. 발견 역할도 권고한 최소 11px에 합의 가능한 범위를 좁혔으며, 320px/긴 JA/light·dark에서 글자 대비와 말풍선 간격을 직접 검수하는 조건은 그대로다. 이는 앱 전체 글자 크기를 낮춰도 된다는 승인이 아니다.

UX-04는 **이번 묶음에서 제외/보류**한다. 발견 평가에서 Restart 진입·취소가 지도 history를 초기화하고 저장 성공 전에 도시 focus를 요청하는 별도 문맥 문제가 확인되었다. 질문 축약을 copy 수정으로 처리할 수 없으므로 현재 전체 reset/취소/저장 실패 시퀀스와 복귀 계약을 먼저 재현해야 한다. 첫 평가의 조건부 찬성을 질문/상태 삭제 승인으로 해석하지 않는다.

UX-08은 **사용자 범위 결정 전 계속 보류**한다. 이 표결은 비금전 해커톤 전용 action 추가나 기존 금융 목업 대체를 승인하지 않는다.

남은 검수는 §5 및 두 평가자의 원 주문/환불/문맥 반례 목록이다. 이 단계에서 새 UI, 명암비, 실제 기기, 전체 여정 PASS를 주장하지 않는다.
