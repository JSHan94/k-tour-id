# UX 변경 결정 원장

상태: **기존 흐름 개선·배포·지정 검수 완료; UX-08은 9/15 사용자 승인 후 구현·검수 중**. 아래 후보 표와 1차 합의는 최초 제안·당시 보류를 보존한다. UX-08의 후속 승인 범위는 마지막 절, artifact별 실제 결과는 [릴리스](./RELEASE.md)를 기준으로 읽는다. 사용자 승인이나 역할 합의를 테스트·배포 완료로 대신하지 않는다.

## 사용자 목적 중심 구조

핵심 객체는 ‘매장과 지금 하려는 일’이다. Wallet/ID는 사용자의 새 목적지가 아니라 그 일을 수행하는 데 필요한 수단으로 등장할 수 있다. 화면 구조를 바꾸되 실제 단계별 동의·처리 상태는 그대로 추적한다.

## 합의 기록 형식

각 결정에 발견/거래/시각 평가자의 독립 제안, 첫 반대 의견, 수정안, 명시 승인/보류 및 PRD 보호 판정을 추가한다. 검토 전 ‘consensus’라고 표기하지 않는다. 상태를 합치거나 핵심 행동을 없애는 변경은 사용자에게 질문한다.

## 1차 한정 합의 원장

근거: [발견](ux-review-discovery.md), [거래](ux-review-transactions.md), [시각](ux-review-visual.md)의 첫 독립 평가와 교차 검토 부록. 조정자는 [PRD 보호 규칙](preservation.md)을 대조했다. 모델·잔액·권한을 합치는 변경은 승인하지 않았다.

| ID | 첫 반론 → 채택 범위 | 1차 동결 당시 상태(현재 결과는 릴리스 참조) |

1차 동결 당시 통합 계약 855/855와 타입 검사가 통과했다. 그 당시 비작성자 리뷰·브라우저 검수·운영 배포는 아직 완료 판정하지 않았다. 이후 862계약·최종 브라우저/배포 결과는 릴리스 기록으로 구분한다.

## 교차 검수에서 발견한 후속 수정

- **AV-01:** 합의한 상세 1:1 비율이 빠져 있어 `compact`를 적용. 실제 어니언 로드/실패 모두 90×90px 확인. 학림 원본 대신 공식 960px/385,996-byte 축소본을 채택했고, 실제 간판 크롭·크레딧·서비스 권한 없음까지 비작성자가 확인했다.
- **AV-02:** 320px JA의 샘플 로드 후 peek CTA가 화면 아래로 밀렸다. 세 역할 조건부 합의는 기존 스크롤 소유권·본문을 유지하고 두 CTA 모두 sticky·불투명 테마 표면으로 표시하는 것이다. 52px CTA·본문 말단 focus, 하단 배경 틈, peek 내부 scroll과 펼친 출처 복귀를 수정·재검수했다. 최종 동일 문서에서 제주 33→33 복귀와 다른 장소 비상속을 확인했다.
- **CODE-06:** Zest 구매 후 My Korea가 고정 영수증/일반 매장명으로 표시하며 복귀 버튼이 없었다. 세 역할은 *선택한 구매*라는 범위를 명시하고 해당 주문의 매장·원결제·확정 환불 ID와 기존 same-place 복귀를 연결하는 한정 수정에 합의했다. 새 전체 원장이나 결제 권한을 만들지 않는다. 다중 주문·부분/잔여 환불과 3종 장소의 지정 복귀 검수가 통과했으며 source별 범위는 sitemap과 비작성자 보고서를 따른다.
- **UX-09 후속:** 다른 구매가 이미 있는데 새 주문을 검토하면 ‘구매 내역 없음’이 목록 아래 함께 노출됐다. 빈 상태는 실제 구매/처리 목록이 0개일 때만 표시하도록 수정했고 다중 주문 검수로 확인했다. 모델·잔액은 변경하지 않았다.

위 후속 변경의 비작성자 판정은 [시각 검수](adversarial-visual-wave1.md), [거래 검수](adversarial-commerce-wave1.md), [조정자 변경 검수](adversarial-root-wave2.md)에 기록한다. 전체 완료나 새 기능 전부 PASS라는 뜻이 아니다.

## UX-08 후속 사용자 결정 — 2026-09-15

- Q1 해결: 사용자가 보류했던 비금전 체험 목업 추가를 승인했다. `feat/ktour-experience-share-20260915`에서 장소 기반 전용 흐름을 추가하며 기존 금융·예약·방문 상태와 분리한다. 앞선 독립 리뷰의 보류는 당시 판단으로 남긴다.
- 한정 범위: canonical Roba 전체 상세의 독립 행 → 비상업적 디지털 동네 가이드 → 현재 유효 Person·목적별 person VP 동의 → 준비된 제안·1회/0원/기한 승인 → 실행/사용/감사 기록의 분리된 결과와 실제 가이드 내용 → 같은 장소 복귀. 국적·체류·성인·Payment KYC는 사용하지 않는다. 실제 CX/OpenDID/Sui/AI/OmniOne 호출과 provider 권한 생성은 하지 않는다.
- 시각/흐름 원칙: 별도 Demo 목적지를 만들지 않고 장소에서 행동을 시작한다. peek에는 세 번째 CTA를 추가하지 않는다. 한 primary 행동, 짧은 sample 안내, 필요한 동의 보존, 실패/unknown과 성공의 구분, 기술 정보는 펼칠 수 있는 보조 설명을 사용한다. 기존 금전 혜택·결제·예약 CTA를 삭제하거나 체험 사용을 방문으로 집계하지 않는다. 매장 제공 쿠폰으로 표현하지 않는다.
- 상태: **사용자 범위 승인 + 구현·검수 진행**. 소스·문구 검토와 아래 실제 브라우저의 한정 판정을 구분하며, 최신 회귀·배포 결과는 새 릴리스 기록을 따른다. 새 기능에 대해 세 역할의 최종 합의/모든 검사 통과를 이 원장만으로 선언하지 않는다. 실제 상태/adapter 계약과 검수 한계는 [체험 목업 인계](../../EXPERIENCE_MOCK_HANDOFF_2026-09-15.md)를 따른다.
- 후속 시각/문구 역할의 **한정 소스 검토 승인**: 단일 상세 진입·한 primary/복귀·실제 가이드·독립 기록 재시도 확인. 실제 동일인 1회 제한/동일인 판정처럼 읽히는 표현은 EN/KO/JA에서 제거했고 Person 확인 여부로 수정했다. 설명/재조회 44px·기록12px를 확인했다. 실제 브라우저·반례·배포 완료는 여전히 별도 검수다.
- 후속 중복 단계 정리: **동일 체험의 현재 Person 결과만** live handoff로 재사용해 두 번째 수단 선택/provider 확인을 줄였다. 새 패스 생성·보관 동의, holder 준비/ack, 목적별 VP는 유지한다. 이 경로의 새 샘플 패스는 Person 전용이며 age/stay는 null, payment0, visitor benefit 없음이다. 전체 발급/다른 자격 확인을 자동 승인하지 않는다. 연결과 실제 검수 결과는 새 릴리스 기록으로 구분한다.
- 독립 시각 실행(`page-0a579e8a35166cb4.js`): 320px JA/dark에서 새 guest의 Person→패스 생성/보관 동의→holder→목적별 VP→키보드 범위 승인→실제 가이드 3개를 확인했다. 480px 높이의 52px footer, 줄바꿈·포커스 테두리·가로 overflow 없음은 PASS. 568px에서 진입한 뒤 480px로 줄이면 같은 장소와 DOM focus는 복구되지만 체험 행이 fold 밖에 남았다. 원인은 snapshot 후 `focus({preventScroll:true})`를 사용하는 기존 복귀 계약이다. 시각 역할은 **experience 복귀에만**, snapshot을 먼저 복원한 뒤 target이 scrollowner/viewport 밖이면 `nearest`로 최소 보정하고 마지막 focus하는 수정에 동의했다. 이미 보이는 target과 다른 서비스·지도 camera/query/disclosure는 변경하지 않는다. 해당 보정의 실제 재검수는 별도 artifact에서 판정한다.
- 위 반례의 최종 재검수: **`5712aed` / `page-7c7e5c4f3603217e.js` 한정 PASS**. 같은 320px JA/dark·568→480 흐름을 새 context에서 다시 실행해 버튼이 scrollowner∩viewport 안에 있고 hit/focus가 유지됨을 확인했다. 전체 캡처 8장을 직접 확인했다. [범위·대표 캡처](./evidence/experience-visual-review-5712aed.md)에 근거를 남기며, 다른 조합이나 배포 완료로 확대하지 않는다.
