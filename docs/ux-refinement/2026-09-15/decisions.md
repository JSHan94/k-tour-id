# UX 변경 결정 원장

상태: **독립 UX 3역할 첫 평가와 교차 검토 후 한정 합의; 구현·실행 검수 진행 중**. 아래 후보 표는 최초 제안과 보호 조건을 보존한다. 현재 판정은 이어지는 합의 원장을 기준으로 읽는다. 합의는 테스트·배포 완료를 뜻하지 않는다.

## 사용자 목적 중심 구조

핵심 객체는 ‘매장과 지금 하려는 일’이다. Wallet/ID는 사용자의 새 목적지가 아니라 그 일을 수행하는 데 필요한 수단으로 등장할 수 있다. 화면 구조를 바꾸되 실제 단계별 동의·처리 상태는 그대로 추적한다.

| ID | 후보 결정 | 기대 효과 | 보호할 것 | 판정/검수 |
|---|---|---|---|---|
| UX-01 | 충전에 진입 문맥 전달: 주문에서는 해당 주문 확인으로, Wallet에서는 잔액으로 | 충전 후 목적지를 예측하고 원 작업을 이어감 | quote lock·재동의·만료·pending operation | 후보. 주문/Wallet 양쪽 UI·취소·만료 왕복 |
| UX-02 | 영수증의 환불 액션 하나로 통합, 전체/부분 선택은 공통 패널 안에서 | 같은 금액에 대한 경쟁 CTA 제거 | 총환불 상한·원 주문/발급 귀속·unknown·hold | 후보. 두 입구 같은 상태/원금·중복 환불 반례 |
| UX-03 | 지원 매장 peek에 서비스 주요 CTA 1개, 길찾기는 보조 | 상세까지 열기 전 무엇을 할 수 있는지 앎 | 미지원/자료형 차이, 명시적 선택·정확 복귀 | 후보. canonical/editorial/research·지원/미지원 검사 |
| UX-04 | 선택형 취향 설정에서 반복 질문 축약 | 지도 진입 후 필요한 개인화만 빠르게 편집 | 자동 게이트 없음·완료만 저장·취소 보존·3언어 | 후보. actual census의 step/action 수로 판단 |
| UX-05 | 매장 중심 주문 요약과 충전/결제 진행 틀 공통화 | 매장·상품·금액·잔액을 이동해도 잃지 않음 | 별도 Payment KYC·구매 동의·전송/매입 경계 | 후보. 한 primary CTA, context/오류/reload 검사 |
| UX-06 | 실제 사진 또는 분리된 음식 예시를 모든 의미 있는 media 슬롯에 연결 | 아이콘 타일보다 매장/음식 판단에 유용 | 사용권·매장 일치·예시 표시·오류 fallback | 후보. asset manifest 승인 및 슬롯별 검사 |
| UX-07 | 동일 pulse frame/event를 지도와 매장 추세/활동에 연결 | 움직임의 의미와 원인이 일치 | 샘플/실제 분리·좌표/자격 불변·interaction 안정 | 후보. 동기화·pause·reduced-motion·성능 검사 |
| UX-08 | 비금전 해커톤 체험을 별도 action으로 명시 | 개발 인계 대표 여정과 목업이 직접 대응 | 실연동 없음·금전/방문 자격과 독립 | **사용자 질의 중**. 기존 앱에 해당 전용 action 없음 |
| UX-09 | 지갑 준비/잔액/충전 문구를 실제 상태와 일치 | 빈 잔액 안내 후 예시 60,000원이 생기거나 잔액 있는데도 ‘먼저 충전’하는 모순 제거 | seed 금액·동의·기존 회계 모델을 임의 변경하지 않음 | 브라우저 020–027 재현. 상태별 copy와 충전 목적의 방법 목록 검수 |

## 합의 기록 형식

각 결정에 발견/거래/시각 평가자의 독립 제안, 첫 반대 의견, 수정안, 명시 승인/보류 및 PRD 보호 판정을 추가한다. 검토 전 ‘consensus’라고 표기하지 않는다. 상태를 합치거나 핵심 행동을 없애는 변경은 사용자에게 질문한다.

## 1차 한정 합의 원장

근거: [발견](ux-review-discovery.md), [거래](ux-review-transactions.md), [시각](ux-review-visual.md)의 첫 독립 평가와 교차 검토 부록. 조정자는 [PRD 보호 규칙](preservation.md)을 대조했다. 모델·잔액·권한을 합치는 변경은 승인하지 않았다.

| ID | 첫 반론 → 채택 범위 | 현재 상태 |
|---|---|---|
| UX-01 | 완료 영수증을 무조건 삭제하면 재처리 위험 → 이미 반영된 완료 화면만 새 방법 선택을 가리지 않게 하고 미확정 작업은 유지. 주문/Wallet 문맥별 복귀 문구 | 구현, 실제 왕복 검수 중 |
| UX-02 | 전체 환불 기능을 없애면 안 됨 → 공통 패널의 부분/잔여 전액 선택을 유지하고 경쟁 버튼만 제거 | 구현, 원 주문·상한·중복 반례 검수 중 |
| UX-03 | 모든 매장에 서비스 부여 금지 → 등록된 샘플 capability만 혜택 primary + 상세 secondary. 미지원 peek 유지, 길찾기는 상세에 유지 | 구현, 정확한 복귀·focus 검수 중 |
| UX-04 | 실제 반복 질문 증거 부족 → 삭제하지 않음. 일반 취향 수정은 이미 한 패널, 명시적 초기화는 선택형 3단계 유지 | 현행 유지. 취소 시 Busan/카페 복구 확인; 정확한 camera/query/scroll은 별도 미검수 |
| UX-05 | 카테고리를 식사로 단정하거나 동의를 합치면 안 됨 → 매장 중립 offer 문구·아이콘, 기존 승인한 같은 결제를 이어간다는 gate 문구 | 구현, 별도 자격·구매 동의 유지 |
| UX-06 | 예시 사진을 매장 사진처럼 쓰면 안 됨 → 출처·권리가 검증된 어니언 로컬 사진부터, alt/크레딧/오류 fallback 포함. 추가 자산은 개별 게이트 | 첫 사진 구현·검수 중; 나머지 후보는 콘텐츠 게이트 기록 참조 |
| UX-07 | 가짜 방문/서로 다른 애니메이션 금지 → 기존 painted frame 공유 유지, Sample 11px로 가독성 개선. 새 timer·autopan 없음 | 구현, 작은 화면·동작 검사 중 |
| UX-08 | 기존 금융 mock을 비금전 Sui 실행으로 간주할 수 없음 → 별도 action 여부 사용자 질의 | 답변 전 보류 |
| UX-09 | UX를 위해 회계 seed를 바꾸면 안 됨 → 기존 ₩60k 샘플 설명, Add funds 목적별 방법, 구매/환불만 있는 기록의 정확한 제목 | 구현, 계약 검사 통과 |

통합 계약 855/855와 타입 검사 통과. 비작성자 리뷰·브라우저 검수·운영 배포는 별도의 단계이며 아직 완료 판정하지 않았다.

## 교차 검수에서 발견한 후속 수정

- **AV-01:** 합의한 상세 1:1 비율이 빠져 있어 `compact`를 적용. 실제 어니언 로드/실패 모두 90×90px 확인. 학림 원본 대신 공식 960px/385,996-byte 축소본을 채택했고, 실제 간판 크롭·크레딧·서비스 권한 없음까지 비작성자가 확인했다.
- **AV-02:** 320px JA의 샘플 로드 후 peek CTA가 화면 아래로 밀렸다. 세 역할 조건부 합의는 기존 스크롤 소유권·본문을 유지하고 두 CTA 모두 sticky·불투명 테마 표면으로 표시하는 것이다. 첫 클릭/52px/본문 말단 focus 검사는 통과했다. 하단 padding의 얇은 배경 틈과 peek 내부 scroll 복귀까지 후속 보정하며 최종 artifact에서 다시 확인한다.
- **CODE-06:** Zest 구매 후 My Korea가 고정 영수증/일반 매장명으로 표시하며 복귀 버튼이 없었다. 세 역할은 *선택한 구매*라는 범위를 명시하고 해당 주문의 매장·원결제·확정 환불 ID와 기존 same-place 복귀를 연결하는 한정 수정에 합의했다. 새 전체 원장이나 결제 권한을 만들지 않는다. 소스 수정 및 첫 실제 구매/부분환불 왕복 통과, 다중 주문 재확인은 진행 중이다.
- **UX-09 후속:** 다른 구매가 이미 있는데 새 주문을 검토하면 ‘구매 내역 없음’이 목록 아래 함께 노출됐다. 빈 상태는 실제 구매/처리 목록이 0개일 때만 표시하도록 수정한다. 모델·잔액은 변경하지 않는다.

위 후속 변경의 비작성자 판정은 [시각 검수](adversarial-visual-wave1.md), [거래 검수](adversarial-commerce-wave1.md), [조정자 변경 검수](adversarial-root-wave2.md)에 기록한다. 전체 완료나 새 기능 전부 PASS라는 뜻이 아니다.

## 질문

- Q1: 하비 명세의 비금전 체험 → 사용자 승인 → Sui 실행 → 사용 결과 전용 흐름을 이번에 목업으로 추가할지 사용자에게 질문했다. 응답 전 관련 신규 구현은 보류한다. 기존 충전/결제·탐색 조사와 개선은 계속할 수 있다.
