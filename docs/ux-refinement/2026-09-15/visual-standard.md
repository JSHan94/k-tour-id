# 이번 개선의 공통 시각 기준

상태: 비교 기준 초안. 기준 캡처는 `k-tour-id-app/artifacts/qa/ux-audit/browser-census/`에 있다. 검수 승인이나 새로운 화면 완성을 뜻하지 않는다.

## 적용 원칙

현재 K-Tour ID의 흑백 지도·카드 구성을 유지한다. 큰 로고/지도 재설계보다 같은 목적의 조작이 같은 위계·용어·상태를 갖도록 수정한다. Toss의 컴포넌트 패턴화·긴 문구·접근성 대응을 주 원칙으로, Revolut의 사용자 용어·재사용·실제 문제 검증을 보조 원칙으로 삼는다. 두 회사의 자산이나 독점 UI kit를 복제하지 않는다.

참고: [Toss 디자인 시스템](https://toss.tech/article/toss-design-system), [Revolut 디자인 원칙](https://www.revolut.com/blog/post/our-top-5-design-principles-at-revolut/). 아래 수치는 K-Tour ID 프로젝트 기준이지 두 회사의 공식 수치가 아니다.

| 항목 | 기준 |
|---|---|
| 색 | 흑백 primary action, 온도·추세에만 기존 색상 의미 유지. After 19와 시스템 테마는 독립 |
| 간격 | 기존 4/8/12/16/20/24/32 체계. 모바일 본문 좌우 16–20px |
| 제목 | 한 화면의 목적 하나. 28–32px 주요 제목, 긴 언어에서 줄바꿈 허용 |
| 조작 | 주요 터치 영역 44px 이상, sticky CTA 52px 이상. 키보드 focus 유지 |
| 패널 | 기존 SheetB 사용. 헤더/스크롤 본문/하단 행동의 소유권 하나씩 |
| 금액 | 결제 금액·사용 가능 잔액 구별, 숫자 tabular. KRW 주표시; 선택한 코인 자산/네트워크는 숨기지 않음 |
| 사진 | 실제 매장 사진과 음식 예시를 별도 media kind로 구별. 고정 비율, 적절한 crop, 오류 시 읽을 수 있는 대체 내용 |
| 모션 | 기존 공개된 온도 frame 재사용. 읽는 중 자동 이동/정렬 없음, reduced-motion·백그라운드 중지 유지 |
| 문구 | 목적에 맞춰 ‘충전 방법’과 ‘결제 방법’을 구별. 준비된 상태에서 ‘먼저’ 같은 선행 조건을 잘못 요구하지 않음 |

## 실제 기준 화면에서 확인한 것

| 캡처 | 유지할 것 | 개선 후보 |
|---|---|---|
| `002-landing-inspect.png` | 즉시 보이는 지도·세 도시, 단일 브랜드, 여백 | 강제 온보딩을 다시 만들지 않음 |
| `027-map-from-wallet.png` | 상단 두 줄, 지도 안 잔액·사용 가능 장소, 타임라인 | 지도/선택 매장에 같은 활동 의미를 전달하는지 확인 |
| `030-research-place-detail.png` | 매장 식별 → 혜택/예약 → 설명 | 권리 확인된 실제 사진, 보조 길찾기 위계, 매장 분류에 맞는 거래 명칭 |
| `031-zest-order-review.png` | 매장명·금액·잔액·별도 동의 | 충전/복귀에서도 같은 매장 맥락. ‘Meal’이 주점 등에도 적절한지 검토 |
| `022-wallet-topup-methods.png` | 짧은 방법 목록과 고정 하단 행동 | 충전하러 왔는데 ‘어떻게 결제?’와 자기 잔액 선택이 먼저 나오는 혼동 |

세 역할의 합의 후 대표 화면 변경부터 구현한다. 자동 테스트 통과만으로 미감을 승인하지 않으며, 같은 화면의 320px/긴 번역/짧은 높이/다크모드 변형을 함께 본다.
