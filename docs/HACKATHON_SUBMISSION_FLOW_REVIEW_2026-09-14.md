# ONDO 해커톤 제출 적합성 — 전체 플로우 검토

검토일: 2026-09-14 · 대상: 제품 책임자·개발자·제출 담당자

## 결론

**기존 3개 기술 인계본만 완료하면 최신 요구인 Sui 추가 바운티까지 충족하지 못한다.** 이번 검토에서 Sui 원문 조건을 확인했고, 인계 범위를 **CX + OpenDID + OmniOne Chain + Sui/AI**로 수정했다.

수정된 명세의 구현·실기기 검수까지 완료한다면, 네 기술을 장소의 서비스 행동에 연결하는 **제출 가능한 통합 MVP를 목표로 한 설계**다. 다만 다음을 별도로 확인해야 하므로 현재 시점에 “제출·상금에 문제 없음”을 확정할 수는 없다.

1. Sui/AI 추가 개발과 A01–A20 실제 증거 확보.
2. 팀의 Sui 등록·별도 제출·참가 조건 및 지원금 적용 확인.
3. 원래 외국인 관광·금융 제안과 이번 국내 신원 기반 MVP의 범위 차이를 최종 제안서에 명시.
4. 결선 제안서·MVP 영상·Sui 추가 자료를 해당 양식·마감에 맞춰 실제 제출.

**방법과 한계:** 공식 가이드·결선 PPTX·원 제안서·현재 코드/문서의 정적 검토다. 지도/일반 UX, 신원/자격, 커머스를 3개 병렬 검토로 나눴고 Sui 프로그램 원문도 별도로 대조했다. 미래 Harvey 구현을 실행해 PASS 판정한 것이 아니며, 현재 목업의 과거 테스트 결과를 실제 연동 증거로 재사용하지 않는다.

기준 앱 소스는 `handoff/harvey-20260914`의 `8c9a264` 스냅샷이다. 이번 v3 문서·추가 명세는 그 이후의 **개발 인계 변경**이다. 같은 인계 브랜치의 최신 문서를 사용하며, 문서 게시와 앱 배포·실제 연동 완료는 구분한다.

## 3. 제출 관점의 주요 발견과 조치

### P0 — 기존 Sui 제외 인계본으로는 최신 목표 미충족

Sui 안내는 단순 wallet 연결·NFT 민팅보다 넓은 요구를 명시한다. 기존 제외/선택 문구를 v3에서 제거했고 HK-06–09·A13–A20을 추가했다. Sui·AI 담당/환경이 확보되지 않으면 네 기술 완료 일정은 미확정이다. 등록/접수 여부도 별도다.

### P1 — 원 제안서와 실제 MVP의 간격

원 제안서 p4–8에는 외국인 여권/eKYC, 체류·서비스 권한, KRW 스테이블 지갑, 결제·정산, AI 추천 등이 있다. 이번 실제 구현은 **국내 모바일 신분증으로 공통 신원→자격→제한된 서비스 실행 구조를 실증**한다. “외국인 관광 금융 서비스 전체 완성”이라고 말하면 시연으로 입증할 수 없다.

최종 제안서에 `이번 실증 / UX 목업 / 후속 연동`을 한 번 명료하게 구분하고, 이 범위가 기존 제안의 MVP로 적절한지 멘토에게 확인하는 것이 좋다. 공개 규칙에서 모든 확장 기능의 상용 연동 의무를 확인하지 못했지만, 축소 범위의 평가상 충분성을 보장하는 근거도 없다. SDK 개수만큼 사업성과 결과 완성도 설명이 중요하다.

### P1 — 기술을 잇는 서비스 행동과 실제 증거

같은 subject·장소·캠페인·intent로 아래가 이어져야 한다.

`CX 서버 검증 → 실제 VC/holder 저장 → VP 검증 → AI 제안·승인 → Sui grant/agent effects → 최종 서비스 사용 → OmniOne receipt`

전부 별도의 실습 화면이거나 mock 승인 버튼·가짜 receipt를 섞으면 대표 여정 완료가 아니다. 구현/검수 의무는 이미 수정 명세에 포함했다. 소비자 CTA에 기술명을 넣을 필요는 없다.

### P1 — 권한과 체인 상태의 혼합

- 실제 CX는 자동으로 Age/체류/Payment KYC 권한을 만들지 않는다.
- zkLogin은 지갑 서명 주체이지 DID 신원/금융 KYC가 아니다.
- Sui consume는 한정 권한 행사이며 최종 혜택 사용과 다르다. 이후 자격 무효면 `fulfillment_blocked`로 남긴다.
- DB·Sui·OmniOne은 하나의 원자적 거래가 아니다. 각 결과·unknown·복구를 분리한다.
- fixture/localStorage·다른 actor·다른 intent의 proof/receipt가 실제 권한을 만들 수 없어야 한다.

이를 새 설계의 명시적 상태와 A01–A20로 다뤘다. 이것은 현재 발견한 실서버 공격 성공 사례가 아니라 **구현 후 반드시 입증할 방어 조건**이다.

### P2 — 실제 데이터·상업 서비스로 읽힐 수 있는 확장 화면

heat/방문 숫자/음식 예시·예약·KRW·정산 UI를 실제 성과로 설명하지 않는다. 지금도 Sample/로컬 계획/예시 사진 등의 경계가 있다. 모든 화면에 기술 경고를 늘릴 필요 없이 제출 영상·범위표에서 핵심 실제 여정과 확장 UX를 구분한다. 실제 매장 제휴가 없으면 체험 혜택도 ONDO 해커톤 체험임을 유지한다.

## 4. 개발자가 완료했다고 할 때 볼 증거

- **정상 1건:** 실제 기기에서 지도→네 기술→같은 장소 결과까지, 동일 버전·동일 intent로 확인.
- **자격 경계:** 미확인/취소/만료/철회/다른 issuer·holder·장소·nonce는 사용 0.
- **AI/Sui 경계:** 승인 밖 agent·대상·추가 전송·prompt injection은 실행 거절, 실제 provenance 변조 검출.
- **중복·복구:** 두 탭·새 지갑·VC 재발급·callback 재전송·서버 재시작·cold return에도 사용 1건.
- **체인 경합:** Sui unknown/consume 뒤 DB blocked, DB used/OmniOne pending을 각각 정확히 표시. 자동 재사용·거짓 rollback 없음.
- **기존 플로우 영향:** 실제 혜택을 써도 KRW 잔액·예약·Age·체류권·방문 수가 바뀌지 않음. 지도는 인증 없이 계속 탐색 가능.
- **제출 안전:** 같은 commit의 URL/영상, 비식별 receipts, 공개 코드·설정·로그·체인 개인정보/secret 점검.

세부 검사는 [1주 명세 A01–A12](./HACKATHON_ONE_WEEK_SPEC_2026-09-14.md#반드시-통과할-12개-검사), [Sui 추가 A13–A20](./HACKATHON_SUI_REQUIRED_ADDENDUM_2026-09-14.md#6-추가-수락-검사--a13a20)를 사용한다. 공급자가 만들 수 없는 장애는 fault injection으로 검증하고 실제 공급자 재현과 구분한다.

## 5. 제출 자료·확인할 사항

- DID: 결선 제안서 + MVP 영상. 공식 가이드의 제출일은 9/21, 팀 안내 시각은 18:00 KST. 최신 메일의 파일 형식·전송 방법·영상 제한을 최종 확인한다.
